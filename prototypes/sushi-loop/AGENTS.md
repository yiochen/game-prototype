# Native UI learnings

- Separate decorative artwork from stable native hit targets when fixed nine-patch corners would enlarge a control's minimum size. Verify actual control bounds and measured font line heights after layout; assigned sizes alone do not prove containment.
- Give wrapped labels a meaningful width before assigning long text, then apply final font and bounds. A zero-width initial layout can leave a stale, oversized height even after the text's true minimum shrinks.
- Block input across the whole visible area of animated overlays, including passive backing exposed during transitions. Cancel both native press ownership and decorative feedback on interrupted touches, backgrounding and window focus loss, without activating an action or changing saved state.
- Exclude historical screenshot evidence from disposable test-project imports. Keep runtime resources and fixtures in the copy, with an isolated save identity, so verification never touches the installed game's data.
- Select scene objects through their rendered sprite pixels, including raised parts above the ground tile. Share the renderer's frame, registration and draw order, ignore transparent padding, and preserve the pointer-to-ground-root offset when moving a selected object. Keep native overlay input shielding and grid placement validation intact; see the [sprite selection contract](godot/review/12/sprite-selection/contract.md).

# Phone performance and art size

- Author world sprites at the catalog scale (256 px per cell) and register them through an ArtBook manifest. The Android build downscales, trims and packs them (`godot/tools/pack_runtime_sprites.gd`); never hand-shrink approved source art. A new sprite folder must be added to `PACKED_SPRITE_TREES` in `tools/build_android.py`, or the build fails.
- Unpacked art (UI, illustrations) ships at its authored size: keep it within 2304 px per side and 3.2 Mpx, sized for a 1344 px-wide phone. The build enforces this, the packed-sprite total and the APK ceiling. Raise a budget only deliberately, with the reason beside it, never just to pass a build. Expedition pieces are exempt but capped until their loader supports packing.
- Never load or decode a texture per frame. Texture loads are synchronous decodes; inside `_draw` or `_process` they stall the frame for tens of milliseconds. Load once and cache, and keep ArtBook's budgeted LRU: never evict atlases merely because the current frame did not draw them. `tests/art_cache_tests.gd` fails if a busy restaurant reloads any atlas within budget.
- Per-frame code must not rescan every object for each item. Build an index once per pass or snapshot (see `_service_index`, `_occupancy` and the belt-link memo in `restaurant_view.gd`).
- Before a release, play the build on a phone for a minute with the performance overlay and check for frames over 100 ms. Profile on the device over adb rather than trusting desktop timing; phone GDScript runs several times slower.

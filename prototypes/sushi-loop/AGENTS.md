# Sushi Loop implementation

- The game target is **Godot Android**. The wireframe site is a design/reference surface and does not replace the native implementation.
- Use Godot's **Mobile** renderer, with **Vulkan on Android** and automatic OpenGL/Compatibility fallback disabled. Verify the actual renderer/driver in GPU checks; macOS uses Metal. Headless simulation tests do not verify Android graphics.
- Deliver Android updates with the original pinned **release** signer, the same package/save identity and a higher version code. Never share a debug-signed APK as an update to the normal installed app. Verify the release certificate and nondebuggable flag before uploading; do not ask the user to uninstall to resolve a signing mismatch.
- Run normal and review Android exports sequentially. Concurrent Godot exports in this workspace failed signing with a missing `AndroidManifest.xml`, despite separate staged projects. Verify each completed APK before starting the next export.
- Work one authorized GitHub implementation ticket at a time and stop for user verification before starting the next ticket.
- For every ticket touching UI, read the [accepted B screen composition](assets/ui/editor/v4/raw/b-indigo-ceramic.png), [Restaurant UI & item catalog](design/art-directions/restaurant-item-catalog.png), [restaurant world concept](design/art-directions/restaurant-concept.png), relevant current wireframe scenes/components and [ART-10 UI workflow](design/art-directions/README.md#ui-reference-workflow-art-10-approved-2026-10-19) before implementation. Expedition UI also checks its underwater catalog and concept.
- Begin UI work with a complete screen composition and a surface/state inventory, covering interactive controls and passive trays, item/profile cards, modal/recovery panels and toasts. Generate a coordinated ImageGen family from that composition and the catalog, considering neighboring controls, shared rim thickness, material, spacing, hierarchy and interaction states. Do not generate isolated controls and assemble unrelated styles afterward.
- Reuse approved UI assets; create corresponding missing or substantially revised UI artwork, including passive container surfaces, through ImageGen with those references. Retain the full original output, exact prompt, reference hashes and provenance. Keep dynamic text/counts out of baked art.
- Never stretch an entire generated button, card, panel or icon to fit a rectangle. Calibrate fixed corners/edges and symmetric content insets; resize only documented plain spans with nine-slice framing or use art at its designed aspect ratio. Preserve icon aspect ratio and scale the complete control family uniformly, without independent horizontal/vertical distortion.

# Native UI learnings

- Separate decorative artwork from stable native hit targets when fixed nine-patch corners would enlarge a control's minimum size. Verify actual control bounds and measured font line heights after layout; assigned sizes alone do not prove containment.
- Give wrapped labels a meaningful width before assigning long text, then apply final font and bounds. A zero-width initial layout can leave a stale, oversized height even after the text's true minimum shrinks.
- Block input across the whole visible area of animated overlays, including passive backing exposed during transitions. Cancel both native press ownership and decorative feedback on interrupted touches, backgrounding and window focus loss, without activating an action or changing saved state.
- Exclude historical screenshot evidence from disposable test-project imports. Keep runtime resources and fixtures in the copy, with an isolated save identity, so verification never touches the installed game's data.
- Select scene objects through their rendered sprite pixels, including raised parts above the ground tile. Share the renderer's frame, registration and draw order, ignore transparent padding, and preserve the pointer-to-ground-root offset when moving a selected object. Keep native overlay input shielding and grid placement validation intact; see the [sprite selection contract](godot/review/12/sprite-selection/contract.md).
- Layout edits may block a guest's route. Do not reserve historical paths or reject an otherwise valid drop solely because a route becomes unreachable. Walking guests first try their assigned seat. If that seat is unreachable but the entrance is reachable, they leave through it; only guests unable to reach either destination wander indefinitely with scared feedback. A departing guest wanders only while the entrance is unreachable. Route recovery preserves fractional position, and a truly trapped guest can resume the original seat when it becomes reachable. Make the departure decision during Live; Edit keeps visit phases, clocks and RNG frozen. Occupied seat moves carry their seated guest. Removal, safe displacement and People rescue follow the #14 customer-recovery contract below. See the [exit-recovery correction](godot/review/12/exit-recovery/contract.md).
- Distinguish admission from a trapped visit: new arrivals without a free, reachable usable seat stand at the entrance for four simulation seconds with the approved puzzled bubble, retry seating during that wait and leave if none opens. They never wander. The approved scared bubble means an admitted guest has no reachable destination or exit; clear it when goal routing resumes. Both feedback clocks pause in Edit and survive save/reopen; see the [entrance and trapped-feedback contract](godot/review/12/entrance-wait/contract.md).

- Customer recovery preserves the same visit, preference, fullness, owned plate and unfinished meal clock. Occupied-seat moves carry seated guests; removing seating leaves a saved standing guest, and suitable seating placed on them reseats immediately. Other objects displace standing guests to a nearest valid empty cell, with atomic rollback if none exists. A stationary 400ms long press picks up any guest from any Edit layer, including seated/eating and entrance-wait visitors; the guest body takes precedence over its stool for holds. A short Layout tap still selects the stool for Rotate/Return. All owned objects support hold pickup and stay selected with context actions after dropping. Early movement pans, selected-object dragging remains available, and cancellation restores the arrangement. See the [long-press amendment](godot/review/14/long-press/contract.md). Clear new reactions until Live, preserve interrupted drops, and hide sushi in all off-stool standing/walking and guest-pickup poses. Keep unfinished meal state paused for reseating; only seated eating poses show the food. The [empty-hands amendment](godot/review/14/empty-hands/README.md) supersedes earlier carried-plate presentation. See the [customer recovery contract](godot/review/14/README.md).

# Approved restaurant runtime subset

`tools/sync_catalog.py` copies these atlases byte for byte from the approved production library. The existing 34-object restaurant selection contains 32 warm, softly lit cartoon refinements and two unchanged floors: 208 base atlases and 2,332 frames. Run it with `--check` to verify selection, manifest provenance and every PNG hash. The manifest retains the complete authored frame, ground root, source scale, animation cadence and attachment sockets.

The game and native component gallery use the same `ArtBook` and `RestaurantView`. Their only geometric scaling is `display_tile_pixels / 128`, applied uniformly to both axes. There is no alpha cropping, pose fitting, per-character height correction or browser contrast filter. The refined models retain their object-specific native camera contracts and source registration. The board's native front-band placement stays in the chef's cell, facing the player, with recipe content composed dynamically. Plates use the native conveyor `deck` socket. Seated character actions already contain the wood-stool support calibration.

Two chef identities, four customer appearances, customer service and restless actions in four directions, all chef actions in four directions, the 24-frame open conveyor, 2D food preferences and the native coin-pop sale effect are included. The approved original heart bubble remains in this base subset; the game's smiling-face feedback lives in a separate registered variant manifest. Recipe and chef food variants likewise extend the base without replacing its approved source pixels. The base catalog plus the separate recipe, chef and smile variants total 252 atlases and 2,860 frames. Other catalog families stay in the source library for later tickets. No Blender authoring project is copied into this Android runtime subtree. The source `.blend` remains preserved in the production library.

Movable plants, barrels, crates, lanterns, stools and straight/open-ended conveyor modules retain all four native facings. Conveyor capture labels describe native object rotation: world east uses `S`, north uses `E`, west uses `N`, and south uses `W`. Each facing preserves the matching incoming/outgoing ports, deck socket and synchronized 24-frame/12-fps running clip. Refinement changes native geometry, materials and lighting while preserving these connection and playback contracts. Original sources, fixed ImageGen targets, saved agent prompts, all review rounds and exact approval bindings remain in the refinement experiments outside this runtime subtree.

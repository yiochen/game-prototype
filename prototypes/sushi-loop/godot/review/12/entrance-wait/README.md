# Issue 12 — entrance wait and trapped-guest feedback

Signed Android **0.4.7 / code 47** implements the [approved behavior](contract.md). New arrivals without a free, reachable usable seat stand at the entrance with a puzzled bubble for four simulation seconds. They retry seating during that wait and leave if none opens. They never wander. Opening a usable seat admits the same waiting guest, preserving identity, appearance and appetite.

Guests already trapped inside keep wandering indefinitely with the scared bubble until their route is repaired. Reopening the route restores their original destination and clears the scared feedback. Seated meals, direct guest-overlap and occupied-seat protections remain. This refines the [0.4.6 wandering behavior](../guest-wandering/README.md).

Both emotions reuse the approved 2D ImageGen artwork, with 12-frame animation clips and the existing head attachment. The scared appearance leads into looping idle feedback; puzzled feedback appears, idles and fades near the deadline. Reduced motion displays a static opaque idle bubble. Persisted feedback clocks pause in Edit and survive backgrounding and cold reopen. Both states are also visible in the Shared components gallery.

# Actual Android APK verification

Signed **0.4.7 / code 47 passed 88 actual Android assertions** on an isolated read-only Pixel 8 / API 35 clone: **55 existing regressions, 15 trapped-wandering/scared-clock checks and 18 entrance-wait checks**. The [summary](android-verification-summary.json), [complete assertion report](android-editor-verification.json), [wandering proof](guest-wandering-verification.json) and [entrance proof](entrance-wait-verification.json) record the successful run. All gameplay changes used real adb taps, swipes and keys, without app-state injection or runtime backdoors. No fixture calibration, test reruns or source changes were required.

The normal **0.4.6 → 0.4.7** installation preserved both save files **byte for byte before first launch**. The [post-launch migration comparison](normal-admission-migration.json) permits only `customer_admission_version=1`, missing `configuration.customers.entrance_wait_seconds=4.0`, and `entrance_wait_elapsed=0.0` / `wander_elapsed=0.0` on each existing guest. Every other expected field is exactly equal except the pre-existing JSON numeric roundtrip at **`remainder`: `0.012927666666409113` → `0.01292766666640911`**, a difference of `3.469446951953614e-18`; the recursive numeric comparison uses tolerance **`1e-7`** and the receipt enumerates the sole changed numeric path. Coins, objects, inventory, guest positions, routes, service progress, meals, visits, simulation elapsed and RNG remain intact. This post-launch comparison is distinct from the exact pre-launch save-byte preservation.

The real layout fixture placed six owned conveyors across row 3 and closed its last gap with a plant at **4,3**, using inventory-card taps followed by world-cell taps. The blocked route was accepted without a purchase, coin change or seated-guest mutation. Inside guests `customer-1` and `customer-3` later entered leaving/wander mode with walk animation and visible scared idle bubbles. Captures show north/south and east/west movement; `customer-1` moved from `(5, 6.2124958)` to `(5.9000092, 5)`. The persisted scared clock advances with simulation, stays frozen through Edit/Home/force-stop and restores on rendered cold reopen. Returning the plant restores goal navigation, resets the scared clock and clears the bubble.

With the route closed again, new `customer-9` stood at the entrance without a seat, preference or wandering mode. Edit/Home/force-stop/cold reopen preserved its exact payload and puzzled feedback clock at **0.05 seconds**. After Live resumed, the puzzled idle bubble was visibly rendered at **1.7 seconds**. The same arrival departed after **3.95 remaining simulation seconds**; every observed pre-departure frame remained `entrance_wait` / `goal`, never wandering. A second real waiter, `customer-10`, remained paused while a spare stool was placed and the plant gate was Returned. It kept its identity, appearance and appetite, claimed `seat-1`, and reached that seat. The native suite separately covers literal occupied-seat release and the deadline-step retry boundary.

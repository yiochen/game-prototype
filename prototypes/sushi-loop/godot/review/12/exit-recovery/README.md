# Issue 12 — reachable exit recovery

Signed Android **0.4.8 / code 48** fixes the guest who keeps wandering scared despite a clear entrance. Previously, a walking guest was classified as trapped whenever its assigned seat was unreachable; the code kept retrying that seat without checking the exit.

Walking guests now try their original seat first. If it is unreachable but the entrance is reachable, they switch to a direct departure with reason `seat_unreachable`, keep their existing walk animation and clear the scared bubble. Only guests cut off from both seat and entrance keep wandering scared. A guest already leaving still seeks the entrance and resumes its original departure when the exit reopens. Guests already seated retain their meals; new unadmitted arrivals retain their four-second puzzled entrance wait.

The decision happens on the first resumed Live step, including for an existing 0.4.7 walking/wander save. Edit remains frozen. Recovery starts at the exact fractional position, without a stand-up animation, teleport, new visit, RNG draw or invented sale. Once a departure starts it keeps its exit destination. See the [behavior contract](contract.md) and updated project guidance.

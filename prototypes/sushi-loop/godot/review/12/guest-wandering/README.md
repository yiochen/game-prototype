# Issue 12 — allow blocked guests to wander

Signed Android **0.4.6 / code 46** implements the [approved blocked-route behavior](contract.md). Valid empty-floor drops may close a guest's route. Historical routes no longer reserve tiles or produce the old walkway rejection. Direct guest overlap, occupied cells, the entrance and occupied-stool guards remain; direct guest overlap now says “A guest is using this space.”

Walking/leaving guests find an alternative route when available. Otherwise they wander indefinitely through reachable free floor using their existing walk animation, retaining the same seat/exit destination and visit. Wandering has no abandonment timer; opening a route resumes the original destination automatically. Seated/eating guests remain seated and continue normal service until they need to leave. Edit freezes all simulation clocks and RNG.

Wandering speed is 65% of normal walking and goal retry is every 0.8 seconds, tuned separately in `content/starter.json`. Reachability uses linear flood fills and reconstructs only the chosen route. Save navigation version 1 records the actual fractional route origin, mode, retry clock and deterministic cursor. Legacy saves validate before neutral migration; their visits, meals, service clocks, RNG, economics and arrangement are preserved. The existing user mobile preview was refreshed and its legacy gameplay fields verified unchanged.

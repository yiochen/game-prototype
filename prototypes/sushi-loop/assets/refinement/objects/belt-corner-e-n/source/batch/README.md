# Conveyor native recipe reuse

This tooling applies the direct user authorized established warm/soft conveyor recipe. It never creates an independent artistic approval. The root coordinator owns frozen briefs, technical acceptance, production promotion, Git and publishing.

The exact family is the native `belt-straight-n/source/round-09.blend` project (SHA-256 `d210743fdff9c17e393d4d2ca59e61c9ea1d5819c2952c10ea40f29b21ff0328`), bound by the approved straight packet and independently approved n-e corner recorded in each `inputs/recipe-policy.json`. The immutable original library SHA-256 is `b1765262bfa897adf7e5de4f2b866cfc939430cf18539f3f7063859b9cff31c6`.

`audit_native.py` reads native authored parent transforms, UV endpoints, source geometry/caps and the stored phase action, writing only an explicitly new audit path. It derives the parent basis chain because saved hidden `matrix_world` values can be stale. Run it with Blender and `-- --out <new-path>`; repeat `--asset <id>` to narrow the read-only audit. The already frozen audit lives one directory above this tooling; do not overwrite it.

`prepare_corners.py`, `prepare_shared_proof.py` and `prepare_caps.py` parameterize the six remaining directed corners and eight start/end variants. They only own their explicitly listed object source/candidate folders and skip sealed packets. Per-object build/capture scripts are copied into that object's portable closure; they do not import sibling runtime code. `run_corners.py` and `run_caps.py` resume only objects without a packet and produce one `READY.json` per completed object. A root technical receipt is still required.

Each build preserves its actual source deck vertices/UV, intrinsic rotation, original authored action and functional ports. The source library stores these actions unbound; each is explicitly restored to the approved family deck material. All have 24 unique frames at 12 fps plus native frame25 closure. Native capture/publication are 2x (384x704), logical frame192x352/root96,248; historical source4x labels remain in untouched source records. Every candidate exports its own 96+4 native captures, original6x4 atlases, actual mixed port assembly and welded reference across all phases. Capture reopens the saved source without running authoring callbacks.

Corner geometry shares the native quarter shape and either directed UV law, with its original intrinsic rotation retained. Curved rails provide an equivalent radial section coordinate field to the exact approved family shader. Supports follow the established curved bearing/rounded leg/cuff/pin construction. Start/end variants reuse exact approved straight rail/support geometry and retain their measured closed U0/U1 terminal, physical cap top0.71939999 distinct from nominal gameplay height0.695. Minor native cap bevel/section adaptation is declared. No final sprite pixel repair, target card, fitting, per-facing recolor or renderer modification occurs.

`measure_template.py` reports exact phase/port/frame/atlas checks and actual registered pixel rotation comparisons. It never assumes pixel identity across compounded float rotations. Native closure exactness is recorded honestly: corners can differ by a few 1-LSB deck pixels at the integer-period closure while phase/alpha remain correct. Full RGB/alpha bounds are retained separately from per-port residuals.

`isolated_consumer.mjs` and its per-object template exercise the actual current SpriteScene/world raster. An OPEN mocked HMR WebSocket is installed before first navigation, with no server connection or forwarded HMR messages. Closing a socket is not isolation because Vite can reconnect/reload. Draw/clear wrappers only record original calls. Every case retains the first actual screenshot before any pixel readback, native canvas readback, and two repeats; URL/atlas byte hashes, painted signatures and navigation events are recorded. A stable-page blank or unstable readback hard-stops with evidence, rather than selecting a favorable recapture. Local HMR access tokens are redacted in new logs.

The broad e-n consumer matrix is reused explicitly by hash. Each new object still runs representative actual facing/phase/size/phone checks. Distinct start/end classes additionally run a small actual unchanged Godot compositor fixture; rotational variants bind that class coverage. No new corner gameplay routing is claimed or introduced.

Packet creation uses the frozen recipe brief and policy. Once a packet exists, do not change any packet-bound bytes or rerun its finalizer. New evidence belongs in a new immutable supplemental packet; art changes require a new numbered round. `seal_isolation_supplement.py` creates such a supplemental binding for a completed isolated diagnostic. The two historical diagnostic probe scripts intentionally refuse to overwrite sealed supplemental output.

Requirements: Blender5.2.2 (tested), Pillow/NumPy for packaging/measurements, repository Playwright/Vite on localhost4178, and Godot4.7.2 for the targeted native compositor fixture. The local bundled Python path in batch runners is an environment executable choice, not a native asset dependency. Native build/capture reproduction requires only Blender, executable per-object recipes and the copied native .blend inputs; the candidate reports contain no image textures or linked-library dependencies.
